# Planner audit — 23 October 2026

## Scope

Reviewed calendar day/week/month navigation, event creation/editing/repetition,
personal/shared visibility and participation, task ordering and completion,
deadlines, upcoming summary, profile/session controls, IndexedDB/outbox,
service-worker caching, push delivery, Google synchronization and traffic policy.
Retired Chat/Together modules remain removed.

## Confirmed defects and fixes

| Area | Defect | Correction |
| --- | --- | --- |
| Month | Event/deadline titles interpolated into HTML | Escape all dynamic text/attributes; mobile browser test uses an HTML-like title |
| Month bounds | Outside-month cells could navigate outside the configured period | Disable cells outside September–December 2026 |
| Local storage | Failed/aborted IndexedDB transactions could leave promises pending or show an uncommitted edit | Reject on abort/error; update UI state only after transaction commit |
| Event conflicts | A deletion response could overwrite a newer queued edit with an older conflict | Check the mutation ID before recording that conflict |
| Offline deadlines | Reminder writes could fail after local event save without a durable retry; cancellation could disappear after cache pruning | Persist pending scheduling/cancellation intents, replay after confirmed event upload, retain failures and skip unresolved event conflicts |
| Reminder correctness | Failed deletion was ignored; obsolete times could be replayed | Check deletion errors; enqueue future times only; cancel completed/deleted deadlines |
| Shared-event notifications | Private-to-shared participation did not queue a push; offline assignment had no durable retry | Queue both assignment paths; persist delivery intent with a stable job ID and idempotent upsert; cancel intent if participation is removed before reconnect |
| Worker push | Failed subscription lookup or complete transient delivery failure could be marked processed | Require a successful lookup/acknowledgement and keep undelivered transient jobs pending |
| Notification navigation | Payload used the old fixed application path | Use a relative URL resolved against the installed service-worker scope |
| Google refresh | Account-level sync failures were logged but reported as success | Return an unsuccessful result/503; do not claim successful initial sync or refresh |
| Manual refresh | The final event-read failure was ignored | Report failure rather than displaying “updated” |
| Authentication | Temporary Auth errors could be interpreted as unauthorized; connect handler could reject outside its catch | Preserve service errors, catch session errors inside the handler, support form submission without a submitter |
| Offline update | An SDK/CDN failure could activate a new app cache without its runtime dependency | Copy the previous valid cached SDK, or keep the existing service worker instead of activating an incomplete update |

## Verification

- Final result: 107 automated tests and 32 real-browser scenario checks pass.
- Unit/regression suite covers existing date/recurrence rules, midnight clipping,
  overlap layout dependencies, conflict merging, revision-only reads, session
  recovery, retry behavior and all new failure cases.
- Real isolated headless Chrome exercises the shipped HTML/modules at a mobile
  viewport with Europe/Moscow timezone and actual IndexedDB.
- Browser scenarios cover saved login, day/week/month, text safety, time fields,
  shared-column expansion, all-day recurrence, offline event/deadline/shared-push
  replay, tasks, cancellation, all plans, upcoming summary and profile validation.
- Browser requests use local mocked Auth/database/push responses. No user account,
  production calendar event or production database row is modified by the tests.
- UTF-8 validation, JavaScript syntax checks and Worker dry-run bundling are run.

## Boundaries and remaining live checks

- No production SQL or RLS policy was changed. Current deployed grants/policies
  must be verified once authorized database access/write service is available.
- This release does not remove the hosting traffic quota/read-only restriction.
- Actual iPhone push delivery and Google/Apple propagation require a live check;
  mocked tests do not establish external service availability or latency.
- Web Push is not an exactly-once protocol. Partial delivery is not replayed to
  already-successful subscriptions; a delivery/acknowledgement network race can
  still cause a duplicate. Per-device durable receipts would need a separate design.
- No guarantee of absence of every possible defect is implied by the tested cases.

Run locally: `npm test`, `npm run build`, `node scripts/smoke-ui.mjs`.
Set `CHROME_PATH` if Chrome is installed elsewhere. The browser uses a temporary,
isolated profile and never attaches to an existing user browser.
